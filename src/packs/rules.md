# 世界的规矩

> 这一层的分界：**改的是门槛与权重，不是事实。**
> 同一份 `records.json` 在任何一条规矩下都是同一批事实（动作、时长、失败、文件名），
> 换个世界包只换「这么过一天，算不算险」「外头更可能发生什么」。

## 一、为什么单独有这么一层

你已经分出来的三层，是按「卖什么」排的：

| 层 | 内容 | 谁来定价 |
| --- | --- | --- |
| 事实层 | `records.json` / `ticks`：动作、时长、失败、文件名 | **永远不卖**，也不许因为付费变准变全 |
| 讲述层 | 一套说法（词表、场景句；曾经有两套：冒险 + 案牍） | 最便宜的付费层 |
| 世界层 | 地点、熟人、场景、世界句、道具 | 最值钱 |
| **规矩层**（这一层） | 什么算危险、什么算收获、外头多容易出事 | **故事包的性格** |

规矩层是「换皮」和「换世界」的分界线。仙侠和规则怪谈如果只换词，
用户三天就看穿；真正拉开差别的是：**同样是改十二次文件，在仙侠里是修为差点走岔，
在规则怪谈里是违了第七条。**

搬进 `scripts/`）：**§1 抓「接线被拆掉」**（2940 格，面板与机器同一个数），
**§1b 照上面这张表自己再算一遍**（同 2940 格，专门抓「语义被改坏」——漏判 `else`、
忘夹 `cap`；末尾还会故意弄坏一处，证明这张网格真有牙）。

`momentOf` 跟前面三个不是一类东西：前三个**算一个值**（多险、落哪一档、讲哪一类），
它**挑一件事实**（那天的经过）。判据也简单——`moments` 是一张列表，按顺序找**第一件每一项都中**的，
一件都不中就是 `null`；一天最多一件，顺序就是优先级。它多认三个项名，名字在
`MOMENT_WHEN_NAMES` 里（`[...WHEN_NAMES, 'hours', 'places', 'scenes']`）。

`directionOf` 是第五台，回答的是**方向**而不是数值：按顺序找第一档「条件全中、且加上这一天还不超上限」
的；兜底那一档（`fallback: true`）不看条件，排最后。上限的算法是
`((已占 + 1) / (之前的天数 + 1)) * 100 <= cap`——**那个 `+1` 不能漏**（漏了上限会一路漂到七成五），
也**恰好卡在上限时放行**（比例停在上限，多一天都不给）。它多认一个项名 `direction`，
名字在 `DIRECTION_WHEN_NAMES` 里，**只在世界层用**（`entry.direction` 是按天算的，单条记录永远不中）。

`choiceOf` 是第六台，**紧跟着 `momentOf`**：那件事挑出来之后，问「走到一半他走了哪条路」。
`choice` 里正好两条路，按顺序找第一条**每一项都中**的；一条都没中就取**最后那条没带条件的**
（所以永远走得出来一条）；没有事件、或者那件事没写岔口，就是 `null`。
它**不认新项名**——路用的还是 `minutes` / `fails` / `deliverables` 那几样，全是按天就能算出来的信号，
**故意不读 `places` / `scenes`**（这样「他这一年都往哪边走」可以按天统计，不必回头重挑句子）。
走的那条会**封在这一件里**（`entry.choice` 是推出来的字段，不写回记录），也没有掷点——
同一份记录看两眼走的是同一条路。

## 三、规矩怎么写（项语言）

一条规矩就是**一串项**，全是数据：

```js
{ when: 'fails', per: 9, max: 4 }                  // 次数 × per，封顶 max 次
{ when: 'minutes', gte: 120, add: 8 }              // 至少这么久
{ when: 'minutes', gt: 60, add: 4 }                // 超过这么久
{ when: 'hour', in: [[23, 24], [0, 5]], add: 14 }  // 时段，可跨零点，末点不含，24 = 一天末尾
{ when: 'place', out: true, add: 8 }               // 位置认不出来（薄世界包）
{ when: 'place', is: ['market', 'guild'], add: 4 } // 在某个地方
{ when: 'tags', has: ['查资料', '翻文件'], add: 16 } // 那天干过这些活
{ when: 'helpers', gt: 0, add: 18 }                // 有人帮手
{ when: 'always', add: 20 }                        // 兜底
{ when: 'outside', bucket: 'road', add: 16 }       // 只在世界层用：他人在野地里
{ when: 'hours', in: [[22, 24], [0, 5]] }          // 只在事件层用：那一格/那一天落在哪个钟点
{ when: 'places', has: ['mine'] }                  // 只在事件层用：那天走过哪几个地方（地点 id）
{ when: 'scenes', has: ['road'] }                  // 只在事件层用：那天走过哪几个场景（场景 key）
{ when: 'direction', is: ['risk'], add: 7 }        // 只在世界层用：那一天的方向是涉险（按天算的，单条记录永远不中）
{ when: 'days', lte: 30 }                          // 只在归宿那一层用：那一年干过多少天
{ when: 'direction', has: ['risk'], share: 40 }    // 只在归宿那一层用：那一年落在这个方向的日子占四成以上
{ when: 'roads', has: ['hold', 'seal'], share: 50 } // 只在归宿那一层用：那一年走过的岔口里一半以上是这几条
{ when: 'fails', gte: 6 }                           // 只在当日计划那一层用：今天撞过六回以上（第十一站那个条件）
{ …, else: true }                                  // 「否则」：紧挨着的上一项没中才判它
```

两条容易踩的：

- **`else` 不能漏。** 代码里写的是 `if (深夜) +14 else if (天黑) +7`——深夜本来就属于天黑，
  漏了 `else` 会加两遍。
- **世界层的权重不是概率表**，是「这种日子更可能听到哪一类消息」；同一个桶中两次就占两项，
  顺序照抄（合并会挪动别的桶在掷点区间里的位置）。

**只能读记录里真有的信号**：`fails` `minutes` `hour` `helpers` `deliverables` `actions` `files`。
想加「下雨」「月相」这类新信号，得先在事实层里有它——否则就是编。

## 五、怎么证明没抄错

规矩里的数字**原来**是从 `client.js` 的函数体里手抄的：抄错一个 9 或 12 不会报警，只会让「他挨打的概率」悄悄变样。
**2026-10-08 接线之后**这件事换了个形状——面板算的就是这份数据本身（`src/client.js:24` 从 `src/packs/rules.js` import 八台引擎，`dangerOf` 只剩一层 `directionBias`），所以「手抄时抄错」从根上不可能再发生；真会发生的是另外两件：**接线被拆掉**、**语义被改坏**。这两件各由对应那一节拦：
所以 `scripts/verify-rules.mjs` 在十万种处境组合上逐个对：

